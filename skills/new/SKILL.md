Read `../../reference/common.md` (relative to this skill's base directory) and run its Step 0 items 1, 2 and 4 (no active task needed).

## 1. Arguments
`$ID` = first word. `$REPO` = second word if it does not start with `--`, else `repos.default`. Options: `--type code|investigate` (default `code`), `--from <task>`, `--refresh`, `--force`.
- `$ID` empty → stop: "Usage: `/task:new <ticket-id> [repo-dir] [--type code|investigate] [--from <task>]`"
- `$REPO` is not a directory in the workspace → stop and list `repos.list`.
Let `$T` = `<tasks_dir>/$ID`.

## 2. Refresh an existing task (`--refresh`)
`$T` must exist and `integrations.ticket` must be configured. Fetch the ticket again following `../../reference/ticket-systems.md` and append only new comments and attachments (rules under "--refresh"). Report what was added and stop.

## 3. Create the task
- `$T` exists → stop: "`$T` already exists. Use `/task:new $ID --refresh` to pull new ticket comments, or `/task:spec` to continue."
- Create `$T/`, `$T/assets/`, `$T/.repo` (`$REPO`), `$T/.type` (`code` or `investigate`).
- **Write `$ID` to `<tasks_dir>/.current` now**, before fetching anything, so data withheld by the gate is sealed inside this task (`$T/evidence/.sealed/`).
- Placeholders for `2_spec.md`, `3_plan.md`, `4_review.md`, `5_report.md`:
  ```
  # $ID — <Spec | Plan | Review | Report>

  <!-- task:placeholder — generated by /task:<spec | plan | review | report> -->
  ```

### 1_requirements.md — first matching case
1. **`--from <src>`** (derive a fix task from an investigation):
   - `<tasks_dir>/<src>` must exist and its `5_report.md` must not be a placeholder; otherwise stop: "Finish `/task:report` of <src> first."
   - `.type` = `code` unless `--type` says otherwise. `.repo` defaults to `<src>/.repo` when no repo argument was given.
   - Write: title, "Derived from task `<src>`" (relative link to `../<src>/5_report.md`), then copy verbatim from `<src>/5_report.md` the answer/conclusion, root cause and proposed next steps, and the ticket reference line from `<src>/1_requirements.md`.
   - The user asked for the fix task explicitly: create it even when the investigation is inconclusive or its review has open blockers. In that case put a warning line at the top of `1_requirements.md` ("⚠️ The investigation <src> is not conclusive: <why>") and repeat it in the final message.
2. **Ticket system configured** (`integrations.ticket`): fetch ticket `$ID` following `../../reference/ticket-systems.md` (everything, read-only, attachments to `assets/`, scanned by the gate). If the ticket is not found or the MCP tools are missing, fall back to case 3 and say why.
3. **Otherwise:**
   ```
   # $ID — Requirements

   <!-- task:placeholder — paste the raw requirement here, then delete this line -->
   ```
